## Read this section first

If you only read one part of one file, read **the diagnosis**.

It's the thing that makes this different from a hook generator. Every case study shows the seven levers scored **before** and **after** repositioning, and names the bottleneck in each state:

> **Bottleneck as given:** surprise + identity (both 1/5). *"Habit tracker for busy professionals"* is a category with zero tension and no tribe. Nobody is against it. Nobody is for it either.

That sentence is the whole product. The hooks are what you get *after* you know that.

Then read **the rejected frames** — the positioning options that were considered and cut, with the reason. A plan that shows no rejected options isn't a plan, it's a preference.

## ⚠️ About the numbers

**There are no impressive statistics in these files, and that's deliberate.**

Every metric is a `[bracketed placeholder]` with a note about what to measure. Each case study ends with a **guardrail check** you can audit:

| Check | Result |
|---|---|
| Invented statistics | None — all counts are bracketed placeholders |
| Invented testimonials | None |
| Guaranteed outcomes | None claimed |
| Single call to action | Yes |
| Platform rules checked | Flagged before posting |

If you're evaluating this repo against others in the category, compare *that table* rather than the star count. A growth tool with fictional case studies on launch day is a liability with a due date.

---

## Three ways these differ from typical growth case studies

1. **The failures are written down.** Every hook has a "how it fails" line. Every plan has a failure condition. Every case study names the thing that would make it wrong.
2. **The alternatives are shown.** Rejected frames and rejected share mechanisms are listed with reasons — you can disagree with the call at each step.
3. **The results are absent.** Because they don't exist. Read [`../CASE_STUDY.md`](../CASE_STUDY.md) for this repo diagnosing itself, including the parts that aren't flattering.

## Adding your own

Run the skill, write it up, open a PR. Good additions:

- **A domain that isn't tech** — a bakery, a local service, a school club
- **A counter-example** — something that looked viral-ready and flopped
- **A run where the skill said "don't launch yet"** — the most useful kind

Keep the placeholders. Keep the guardrail check. Keep the failure condition.
