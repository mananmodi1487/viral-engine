# Ethics incidents

Times this ecosystem did harm, recorded so that the design decisions that allowed it can be
changed.

This directory is not a hall of shame. It exists because the alternative — only publishing
ethics *policies* — produces beautiful principles that have never been stress-tested against
a real failure.

## What belongs here

| Kind | Example shape |
|---|---|
| A tool did something harmful | a growth tool that generated fake testimonials by default |
| A metric drove bad behaviour | an engagement dashboard that rewarded outrage |
| A safety feature harmed the careful | `2026-04-safety-feature-as-censor.md` |
| A community norm decayed | astroturfing becoming normalised on a launch platform |
| A dataset was misused | scraped profiles used to personalise outreach |

## Rules

1. **Name the mechanism, not a witch.** "An outreach tool whose default was 500 DMs/day"
   is a useful record. "Company X is evil" is not, and will be edited or rejected.
2. **Every record carries a label**, like every other record in this repository.
3. **If it is ours, it goes first.** We do not get to publish other people's incidents while
   omitting our own; there is one of ours already, and it is the oldest file here.
4. **The remedy is recorded, or the incident is marked open.** An incident with no remedy is
   more honest than an incident with a false one.
5. **No personally identifying detail about private individuals**, ever, including in a
   record about harm. Redact.

## What this directory cannot do

It cannot make anyone act. It cannot verify most incidents, because the people harmed are
often not the people with the logs. And it will always be biased toward incidents that
produced a public argument, which excludes the quieter and more common harms.
