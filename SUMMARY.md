# 📈 Launch Playbook

**How a skill like this actually gets stars — and what it would really take to reach 100K.**

---

## First, the honest bit

You asked for a repo that reaches 100K+ stars. Here's what that number means, because planning around a fantasy is how projects get abandoned in week three.

| Reality | Detail |
|---|---|
| **100K stars is ~0.008% of repos** | Roughly 150–200 repositories on all of GitHub have ever passed it. Ever. |
| **Stars are a distribution event, not a quality score** | Nearly every 100K repo had one moment: a Hacker News front page, a famous person's post, a viral demo, or years of compounding search traffic. |
| **The median "good" repo gets 5–50** | Reaching 500 puts you in the top few percent of all repositories. |
| **Nobody can promise it** | Anyone guaranteeing a star count is selling something. |

**So what's the real target?** **1,000 stars in 90 days.** Ambitious, achievable, and it's roughly the threshold where GitHub's own recommendation surfaces start feeding you traffic for free.

> Every number in this playbook is a **planning estimate**, not a measurement. Replace them with your own data as you go.

---

## Why this specific repo can compound

Four structural advantages, and one honest gap.

1. **It's a skill, not a library.** Zero install friction, no dependencies, no API key. The barrier is "copy one file."
2. **The output is the marketing.** People run it, get a reframe, and screenshot it. The tool manufactures its own material — but only if the output is specific enough to screenshot, which is the single biggest risk here.
3. **The research backbone is real.** Four cited findings that contradict common advice give it something to say that isn't a vibe.
4. **Honesty is the differentiator.** The growth space is drowning in invented case studies. Being the tool that refuses to invent numbers is defensible — and it's why the output gets trusted enough to be used.

**The gap:** there's no benchmark, no network effect, and no 5-second "wow" demo. The before/after card is the closest thing, and it's a static image.

---

## The highest-leverage asset: the before/after

Not a blog post. **One image.**

```
IN:   "A daily habit tracker app for busy professionals"
              ↓
OUT:  "It's not a habit tracker. It's placement-risk management."
```

**Why it works:** the reframe is legible in under three seconds, it's surprising, and it teaches the reader something they can reuse on their own project immediately. That's the whole share trigger, and it costs the sharer nothing.

**Action:** produce 5 of these from 5 different domains (a bakery, a B2B SaaS, a newsletter, a student club, a side project). Post one per week. They never expire and they're reusable forever.

## The launch sequence

### Phase 0 — Before you say anything (Week 1)

A launch that lands on a broken repo converts zero.

- [ ] `SKILL.md` works end-to-end from a clean Claude install — test 5 times, different inputs
- [ ] Both example JSONs validate
- [ ] README renders on mobile (check the badge row and the tables)
- [ ] Repo topics set: `claude-skill`, `claude`, `ai`, `marketing`, `content-creation`, `viral`, `growth`, `prompt-engineering`
- [ ] Social preview image set (Settings → Social preview) — this is the card on every share
- [ ] Discussions enabled, one pinned thread: "Show me what Viral Engine gave you" — every reply is a real testimonial

**Gate:** don't launch until 10 strangers have used it and 5 reported something useful. Friends compliment. Strangers report.

### Phase 1 — The first 100 (Week 2)

Hand-to-hand, not broadcast.

- [ ] Give it to 20 people with a real launch coming up, individually
- [ ] Ask for **their output**, not their opinion
- [ ] Collect the 3 best outputs — screenshots only, permission asked, **no invented quotes**
- [ ] Add those 3 to the README. First time the README is allowed to claim results.
- [ ] Post the *story* to one community whose rules allow it

### Phase 2 — The public attempt (Week 3–4)

One coordinated push. Timing matters more than volume.

| Channel | Format | Notes |
|---|---|---|
| **Hacker News** | Show HN, Tue–Thu, 8–10am ET | Plain, non-promotional title. Survival is measured in minutes — be present for 6 hours. |
| **r/ClaudeAI, r/ClaudeCode** | Build story, not an ad | Read the self-promo rules first. Answer questions for a week before linking. |
| **X / LinkedIn** | The before/after card | Lead with the output. Link goes in the reply, not the post. |
| **Product Hunt** | Launch with a real demo | Needs a visual. The before/after card is it. |
| **Claude skill directories** | Submit everywhere | Low effort, long tail, keeps working for months |

**You get one real HN attempt.** Don't burn it on an unpolished README.

### Phase 3 — The long tail (Month 2+)

The spike is luck. The tail is work. This is where 90% of repos die and where 1,000 stars actually comes from.

- [ ] **One new example per week**, different domain, always complete
- [ ] **A short "why we cut this frame" post** per example — rejections are more interesting than results
- [ ] **SEO surface**: filenames and README mention the domain (habit tracker, newsletter, B2B, bakery). Repos rank in Google; GitHub search is free distribution.
- [ ] **A recurring artifact** — "pattern of the week" — that converts a one-time reader into a returning one
- [ ] **Invite 3 contributors by name.** Three outside contributors reads as alive; 3,000 stars and one committer reads as abandoned.

## The loop

```
Useful skill → surprising output → screenshot → someone else
     ↑                                            │
     └──────── new example / PR ←─────────────────┘
```

Every run is a content opportunity. Every shared output is a new user who produces another one.

**What breaks it:** outputs that read as generic. A skill returning "post consistently and provide value" produces no screenshots, and with no screenshots the entire mechanism collapses. Specificity isn't a style choice here — it's the load-bearing wall.

---

## Scorecard

Weekly. Three numbers. No vanity metrics.

| Metric | Why | Working | Broken |
|---|---|---|---|
| **Stranger runs** | Installs by people you don't know | > 30/week | Only your own network |
| **Output shares** | People posting their results | > 5/week | Used privately, never mentioned |
| **Star-to-run ratio** | Do users convert to stargazers? | > 20% | High runs, low stars → README isn't asking |

Supporting signals: repo views → clones, issue quality (real use cases vs. "cool project!"), returning visitors.

## The realistic curve

| Timeframe | Optimistic | Realistic | Fail state |
|---|---|---|---|
| Week 1 | 150 | 40 | 5 |
| Month 1 | 1,200 | 300 | 30 |
| Month 3 | 4,000 | 1,000 | 150 |
| Month 12 | 15,000 | 3,000 | 400 |

**100K requires a genuine outlier** — HN front page *and* a major account picking it up *and* examples good enough to sustain it. Possible. Not plannable. Plan for 1,000 and you might get the outlier; plan for the outlier and you'll get 40.

### Go / no-go gates

- **Week 2:** < 10 stranger runs → the **audience** is wrong, not the copy
- **Month 1:** good runs, weak stars → the README isn't converting. Rewrite the top 10 lines only.
- **Month 2:** good stars, no returning users → a novelty, not a habit. Ship recurring value or stop investing.
- **Any point:** hostile replies about accuracy → stop promoting, fix the claim. Reputation compounds in both directions.

---

## What will actually kill this

1. **Generic outputs.** The #1 risk. No screenshots → no loop.
2. **Overpromising.** "Make anything go viral" invites "nothing can make anything go viral." The honesty policy exists to prevent this — keep it in the marketing too.
3. **One fabricated testimonial.** The replies become the story, and the story is that you made it up. The entire differentiator is that this repo doesn't do that.
4. **Launching before it's good.** One burned HN attempt can't be repeated.
5. **Stopping at launch.** Week 3 is the filter.

---

## The one-line version

> Build something specific enough that a stranger screenshots it, honest enough that they trust it, and cheap enough that they try it in 60 seconds — then ship one new example every week for a year.

Everything above is execution detail.
